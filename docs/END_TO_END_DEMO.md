# KhetAI End-to-End Demo & Hardening Specification

> **Mandatory Architecture & Provenance Disclaimers**:
>
> 1. *KhetAI currently uses simulated sensor data for software development and demonstration. No physical IoT hardware is connected.*
> 2. *The current irrigation recommendation is generated by an agronomic calculation baseline. The ML layer is experimental and is not represented as a trained production model unless sufficient genuine historical data becomes available.*

---

## 1. System Workflow Overview

KhetAI provides a complete software decision-support pipeline for sugarcane farmers:

```
[Farmer Registration / Login]
         │
         ▼
[Plot Setup / Selection] ──► (Soil Profile + Crop Planting Date)
         │
         ▼
[Telemetry & Weather Ingestion]
  ├── Sensor Telemetry (SIMULATED) ──► Data Quality & Freshness Gate
  └── Weather Forecast (LIVE_API via Open-Meteo) ──► 6-Hour Cache / Fallback
         │
         ▼
[FAO-56 Agronomic Irrigation Intelligence Engine]
  ├── Crop Water Requirement (ETc = Kc × ET₀)
  ├── Available Water Capacity (FC - WP) & Depletion Budget
  └── Yield Loss Risk Exposure Assessment
         │
         ▼
[Multilingual Advisory & Decision Display]
  ├── Core Answers: Should I Irrigate? When? How Much? Duration? Why?
  ├── Provenance & Trust Bar (SIMULATED sensor | LIVE weather | Agronomic calculation)
  ├── Demo Scenario Controls (Normal, Low Moisture, Rain Expected, Stale Sensor)
  └── Experimental ML Status Panel (INSUFFICIENT_HISTORICAL_DATA)
```

## 4. Data Provenance & Trust Model

KhetAI strictly communicates data origin across all API responses and UI cards:

- **Sensor Data**: `SIMULATED` (Always labeled as simulated demo telemetry)
- **Weather Forecast**:
  - `LIVE_API`: Fresh live forecast retrieved from Open-Meteo
  - `CACHED_API`: Served from PostgreSQL 6-hour cache
  - `FALLBACK`: Historical seasonal temperature fallback when network is offline
- **Recommendation Engine**: `AGRONOMIC_BASELINE` (FAO-56 crop physics)
- **ML Layer**: `INSUFFICIENT_HISTORICAL_DATA` (Transparently reports active baseline)

## 5. Farmer-Facing Advisory Interface

The advisory hero interface answers 5 fundamental farmer questions:

1. **Should I irrigate?** — Prominent Decision Badge (`IRRIGATE NOW`, `MONITOR`, `NO IRRIGATION`)
2. **When should I irrigate?** — Immediate timing recommendation (e.g. *Today / Immediately* or *In 3 days*)
3. **How much water should I use?** — Recommended volume in \(m^3\) (e.g. *120 m³*)
4. **For how long?** — Recommended pump runtime in hours (e.g. *2.5 hours*)
5. **Why?** — Plain-language reasoning bullets explaining soil moisture depletion, Kc stage, and ET₀ demand.

---

## 6. Irrigation History & Security Controls

- **Logging**: Farmers log pump runs (`durationHours`, `waterAppliedM3`).
- **Persistence**: Saved directly to PostgreSQL `IrrigationEvent` table.
- **Security & Cross-User Isolation**:
  - All plot queries enforce `plot: { farm: { ownerId: userId } }`.
  - User A cannot view, modify, log irrigation for, or read alerts belonging to User B (enforced by 404 responses).
  - Rate limiting (300 requests / 15 min) and request tracing (`X-Request-Id`) active across all endpoints.

## 7. Demonstrating the Experimental ML Analysis Panel

When presenting KhetAI to evaluators or stakeholders:

1. **Locate the Panel**: Navigate to the **Irrigation Advisory** view and scroll below the main recommendation card and scenario buttons to locate the **Experimental ML Analysis** panel.
2. **Present as Secondary Analysis**: Explain that the ML model is trained on an external sugarcane research dataset (Zenodo DOI: `10.5281/zenodo.19725692`) and serves as an experimental secondary signal for research comparison.
3. **Clarify Non-Interference**: Emphasize that the ML model **does not override** the primary FAO-56 Agronomic Baseline recommendation.
4. **Explain Unit & Scale Non-Comparability**: Highlight that the ML prediction unit (`LITERS_PER_DAY_DATASET_SCALE`) is derived from an external model simulation and is explicitly marked as `NOT_DIRECTLY_COMPARABLE` to KhetAI's plot-level event calculation (\(\text{m}^3\)).
5. **Show Transparency & Provenance**: Point to the test-set metrics (\(R^2 = 0.8507\) original scale, \(R^2 = 0.9421\) log scale), the feature provenance breakdown, and the prominent scientific disclaimer callout.

## 8. Known Limitations & Software Scope

1. **Hardware Scope**: KhetAI is currently a software platform demonstration. Sensor telemetry is generated by a deterministic simulator.
2. **ML Model Status**: The ML pipeline features a trained model (`sugarcane-irrigation-v1`) on external research data (`10.5281/zenodo.19725692`), but uses the agronomic engine for active recommendations until on-farm IoT dataset collection is completed.
3. **Database Dependency**: In production environments, PostgreSQL is required for multi-tenant data persistence and caching. When disconnected, `/api/ready` returns `503 Service Unavailable`.
